#+title: excal.el — Excalidraw on Emacs Canvas (spike)

Path-exploration spike: .excalidraw files are parsed in Elisp, rasterized by a
Cairo/Pango dynamic module straight into an Emacs 32 Canvas pixel buffer, and
edited with mouse/keyboard commands.

* Build and test

#+begin_src shell
make            # builds excal-module (.so/.dylib/.dll per Emacs; needs cairo, pangocairo)
make info       # shows the detected platform, Emacs, header and module name
make test       # batch ERT: round-trip, text, rendering, tiles, resizing
make try        # opens the sample in a clean GUI Emacs
make bench      # benchmarks backends in a clean GUI Emacs, writes bench.txt
#+end_src

* Try it

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/excalidraw")
(require 'excal)
(excal-open "test/sample.excalidraw")   ; or (excal-new)
#+end_src

| Key            | Action                                  |
|----------------+-----------------------------------------|
| =v r o d a l p t= | select / rectangle / ellipse / diamond / arrow / line / pen / text |
| drag           | draw with tool; move selection; pan on empty space |
| drag a handle  | resize the selection (text scales its font) |
| double-click   | edit text under the pointer, or add text there |
| wheel, C-wheel | pan, zoom at pointer                    |
| =e=, =RET=     | edit selected text, previewed live; =C-j= newline, =C-g= cancel |
| =DEL=          | delete selection                        |
| === =-= =0=    | zoom in / out / reset                   |
| =H=            | toggle 1x/2x canvas resolution          |
| =b=            | cycle presentation backend              |
| =B=            | benchmark pan, drag and zoom         |
| =C-x C-s=      | save back to the .excalidraw file       |

* Presentation backends

The module renders into its own offscreen framebuffer; =excal-backend=
chooses how that reaches the screen:

- =canvas= — copy every frame into one Canvas image.
- =tiles= — split the window into Canvas tiles; the module diffs each
  tile against its last contents and only changed tiles get
  =canvas-refresh=.  Drags also repaint only the damaged rectangle.
- =layer= (macOS) — a CoreAnimation layer over the Emacs view shows the
  framebuffer via IOSurface, bypassing =canvas-refresh=.  Mouse events
  still go to Emacs.
- =auto= (default) — =layer= on graphical macOS frames when the module
  was built with it, =tiles= everywhere else.  An explicit choice wins.

Independently of the backend, rendering only repaints what changed:
elements outside the view are culled, drags repaint the damaged
rectangle, and panning by whole device pixels shifts the framebuffer in
place and paints only the newly exposed strips (sub-pixel trackpad deltas
accumulate first).  Zooming (C-wheel, pinch, === / =-=) shows a preview
first: the module scales the pixels of the last full render about the
anchor with bilinear filtering (about 0.5 ms at 1x, 2 ms at 2x), and a
crisp full render follows once no zoom step came for
=excal-zoom-preview-delay= (0.1 s; nil renders every step fully).  Steps
more than =excal-zoom-preview-limit= (4x) away from that render render
fully.

=M-x excal-bench-backends= in an excal buffer compares them; =make bench=
does the same in a fresh GUI Emacs and writes =bench.txt=.

* Layout

- =src/excal-render.c= — roughjs-style strokes, hachure fills, Pango text.
- =src/excal-module.c= — module glue, framebuffer, tile diffing.
- =src/excal-preview.c= — zoom previews scaled from rendered pixels.
- =src/excal-layer.m= — CoreAnimation overlay backend (macOS).
- =excal-core.el= — module loading, shared state, document model.
- =excal-view.el= — framebuffer, presentation backends, damage, scroll
  reuse, pan/zoom, export.
- =excal-edit.el= — hit testing, resize handles, pointer, tools, text.
- =excal-bench.el= — backend benchmarks.
- =excal.el= — keymap, major mode and entry points.

* Known gaps

Not ported: perfect-freehand (pen strokes are smoothed polylines), arrow
bindings, groups, frames, images, undo, rotation (rotated elements cannot be
resized), text inside shapes, collaboration.  Text is typed in the
minibuffer with a live preview rather than on the canvas.  Rough strokes resemble but do not match the web
renderer pixel for pixel.  Excalifont is used when installed; otherwise text
falls back to PingFang SC.
